### Terraform dependency graph (generated by `terraform graph` in the pipeline)

![terraform graph](terraform/outputs/graph.svg)

Arrows point from a resource to what it **depends on**. Terraform builds this DAG and creates independent branches **in parallel** (the S3 branch and the network branch run at the same time). It destroys them in **reverse** order.

## How the project demonstrates each concept

| Concept | Where in the code |
|---|---|
| **Providers** | [versions.tf](terraform/versions.tf) pins `hashicorp/aws ~> 5.0` + `hashicorp/random ~> 3.6`. [provider.tf](terraform/provider.tf) configures the region and `default_tags` that every resource inherits |
| **Variables** | [variables.tf](terraform/variables.tf): region, project, environment, CIDRs, instance type, AMI, SSH CIDR (typed, with defaults and descriptions). Values in [terraform.tfvars](terraform/terraform.tfvars). In CI, `TF_VAR_ami_id` overrides the AMI |
| **Resources** | 12 in total: [network.tf](terraform/network.tf) (VPC, subnet, IGW, route table, association, SG), [compute.tf](terraform/compute.tf) (EC2), [storage.tf](terraform/storage.tf) (random_id, bucket, versioning, public-access block, object) |
| **Data source** | `data.aws_availability_zones.available` picks the first AZ instead of hard-coding it |
| **Outputs** | [outputs.tf](terraform/outputs.tf): VPC/subnet/SG/instance IDs, public IP, URL, bucket |
| **Implicit dependencies** | Any reference, e.g. `vpc_id = aws_vpc.main.id`, `subnet_id = aws_subnet.public.id` |
| **Explicit dependency** | `depends_on = [aws_route_table_association.public]` on the EC2 instance: user_data runs `dnf install nginx` at boot, so the internet route must exist first even though nothing in the instance references it |
| **State** | `terraform state list` after apply (12 addresses) and empty after destroy; `plan` re-reads state + reality |
| **plan / apply / destroy** | Full run below |

Security choices: SSH only from one `/32`, IMDSv2 required (`http_tokens = "required"`), encrypted root volume, S3 public access blocked, versioning on.

## Where it ran (honest note)

![GitHub Actions - Terraform workflow (sessions 18 + 19)](screenshots/actions-terraform-run.png)


No AWS credentials are configured for this repo, so the GitHub Actions pipeline runs Terraform against **Moto**, an open-source AWS API emulator running as a service container. A CI-only `ci_moto_override.tf` points the provider's endpoints at it. The code itself is plain AWS Terraform and runs unchanged against a real account with `aws configure && terraform apply`. The CI picks an AMI ID from Moto's catalogue because the real Amazon Linux AMI ID doesn't exist in the emulator.

### apply
Notice the order in the log. The **whole S3 branch** (random_id → bucket → versioning/public-access/object) finished **while the VPC was still being created**, because the two branches run in parallel. After the VPC: IGW, subnet and SG in parallel, then the route table, the association, and **only then** the EC2 instance. That's the dependency graph in action.

## Run it yourself against real AWS

```bash
cd "Cloud Terraform/terraform"
aws configure                              # an IAM user/role with VPC, EC2, S3 permissions
terraform init
terraform plan -var="allowed_ssh_cidr=$(curl -s ifconfig.me)/32" -out tfplan
terraform apply tfplan
curl "$(terraform output -raw web_url)"     # -> <h1>Hello from devops-heros (Terraform)</h1>
terraform destroy                          # avoid charges
```

## Lessons learned
- Split files by concern (network/compute/storage) and keep values in `tfvars`. The same code can then serve dev and prod with different var files or workspaces.
- `plan` before every `apply`, and save the plan in CI so the apply is exactly what was reviewed.
- Most dependencies come for free from references. Use `depends_on` only for hidden ones (like user_data needing internet).
- State is precious: remote backend + locking in teams, never in Git.
- Emulators like Moto/LocalStack are great for CI and learning, but not 100% faithful (the IMDS drift above). Final validation belongs in a real sandbox account.
